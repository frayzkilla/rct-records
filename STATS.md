# Дашборд `/stats`

Страница доступна без авторизации, исключена из индексации и отсутствует в основной навигации. В админке есть ссылка «Статистика». Логины и сводная активность администраторов на дашборде публичны.

## Развёртывание

На Linux VPS выполнить `docker compose up --build -d`. Таблицы аналитики создаются автоматически, каталог и медиа сохраняются. Дополнительные секреты не нужны.

Сервис `metrics` доступен только внутри Docker-сети, порты наружу не публикуются. Он читает `/proc`, `/sys` и корневую файловую систему хоста через подключения только для чтения. Privileged-режим и Docker socket не используются. Корневой диск измеряется через `/host/root`, сеть — через `/host/proc/1/net/dev`; виртуальные интерфейсы Docker исключены.

Бэкенд обращается к `METRICS_COLLECTOR_URL=http://metrics:9101`. Без переменной измеряется локальное окружение с соответствующей подписью. При недоступности сборщика инфраструктурный блок показывает ошибку; аналитика сайта работает независимо.

## Ресурсы и медиа

Метрики вычисляются при открытии страницы и по кнопке «Обновить». Нет фонового сбора, сохранения снимков, кэша результатов или исторических графиков инфраструктуры. CPU и скорости измеряются за интервал около 300 мс. Одновременные запросы используют одно выполняющееся измерение.

При каждом запросе подсчитываются количество и размер аудиофайлов и изображений в проектном `storage`, включая файлы удалённых записей. Символические ссылки не обходятся. Количество треков в каталоге показывается отдельно.

Не настраивать периодические healthcheck-запросы на `/snapshot` или `/api/stats/server`: каждый запрос выполняет измерения.

## Аналитика сайта

Случайный UUID браузера хранится в localStorage; при недоступности хранилища используется временный идентификатор. Новый визит начинается после 30 минут бездействия. Просмотры `/stats`, административных и неизвестных страниц исключены. Прослушивание — фактический старт нового запуска трека; паузы, буферизация и перемотка не увеличивают счётчик. Работающий на `/stats` плеер продолжает отправлять события прослушивания.

Успешные входы/выходы и изменения контента/аккаунтов фиксируются сервером. Пароли, токены, IP и полные URL в аналитические таблицы не записываются. История сохраняется после удаления треков или аккаунтов.

Подробные события хранятся 90 дней, дневные агрегаты и идентификаторы уникальных браузеров по дням — до 365 дней. Фоновая агрегация и очистка выполняются раз в час, без измерения ресурсов или хранилища. Время хранится в UTC, календарные периоды показываются в UTC+8 (Иркутск). «24 часа» — текущий и 23 предыдущих часа; остальные периоды включают текущий календарный день. Аналитика обновляется раз в минуту, инфраструктура — вручную.

Текущий Compose запускает один экземпляр backend. Для нескольких экземпляров потребуется один выделенный процесс агрегации.

## Проверка после обновления

- Открыть `/stats` без входа и перейти туда по ссылке из админки.
- Сравнить CPU, RAM и диск с `top`, `free`, `df` на VPS. Проверить ручное обновление. При закрытой странице измерения не выполняются.
- Открыть публичные страницы, запустить аудио, проверить паузу, перемотку и новый запуск.
- Выполнить изменение контента администратором и проверить графики активности.
- Перезапустить backend и убедиться, что аналитика сохранилась.
